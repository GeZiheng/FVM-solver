# OpenFOAM 对照排查

目标：把"我们的实现与参考实现不一致"从**猜测**变成**带判据的结论**。手段是让 OpenFOAM 跑同参数算例，与我们的输出逐单元/逐面比对；差异定位不了时再读 OpenFOAM 源码解释它为什么不同。

这条路径有效的前提是：**先把差异缩小到一个单步、同一个方程上**，再谈稳定性/累积误差。

## 工作流

1. **写对照契约**：列清"哪些必须相同"——网格与几何、物性、时间格式、对流格式、所有边界条件、Δt、线性求解器容差，**以及算法配置（`nCorrectors`、松弛因子、`momentumPredictor` 等）**。任何一项不同，对照就无效。
2. **单步指纹**：两边都跑**一个时间步**，逐单元/逐面比字段。一致到求解器容差量级（~1e-11）才算"第一步没问题"。不冻结这一步，后面的发散就无法区分"第一步就错"和"累积放大"。
3. **多步/多配置扫描**：跑到发散（或到关注时刻），用"配置写进目录名"的独立算例逐个变量扫。想解释机制时，**先写下可证伪的预测再跑**（例：假设"Δt 变小就能救单修正子"→ 实测三个 Δt 全发散 → 假设被推翻，如实记录）。
4. **读源码解释差异**：对照数据只能说明"哪里不同"，源码才能说明"为什么不同"。先查 `references/openfoam-facts.md` 里已确认的事实，避免重复读源码。
5. **固化结论**：把结论写进 `docs/<模块>.md`（本项目约定：结论 + 判据 + 已排除清单），再交给 `refactor-code` 走改码流程。

## 硬约束

- **不修改 OpenFOAM 源码**（除非用户明确同意），只改算例配置（`fvSolution`/`fvSchemes`/边界文件）。想验证"某个设置有没有影响"就换算例配置。
- **每个配置一个独立算例目录，并把配置写进目录名**。混用不同配置的输出会得出完全错误的结论（本项目曾因此误判"边界通量差 2.7 倍"）。
- **区分"已确认 / 已排除 / 待查"**，每条都带判据（哪个实验、哪段源码、什么量级）。已排除项要写清楚，避免重复试错。
- **不以放松阈值、换算法、跳过断言的方式掩盖缺陷**；对照的目的是找到并修掉真问题。
- 优先问**结构性**问题："两个实现解的是不是同一个方程？哪个量在两步之间变了？"这比调求解器参数有效得多。

## 环境

- WSL 里有已编译的 OpenFOAM-14：源码 `~/OpenFOAM/OpenFOAM-14`，算例根目录 `~/OpenFOAM/gzh1057-14/run`。
- WSL 访问需要提权（`sandbox_permissions=require_escalated`）；`source .../etc/bashrc` 之前要 `set +u`。
- **把命令写成脚本文件再执行**，不要用带 `()`、`<>`、`$()` 的长内联命令（PowerShell→bash 的引号/转义会破坏它们）。临时脚本放在仓库里（如 `.tmp_<用途>.sh`，用 `bash /mnt/d/Projects/FVM-solver/<脚本>` 调用），用完删除；日志与中间产物放 `%TEMP%`。
- 本项目源码必须保持**纯 ASCII**（MSVC 报 C4819）；中文文档在 PowerShell 里要用 `-Encoding UTF8` 读。

## 资源

- `references/comparison-case.md`：搭同参数算例、运行、提取场、面/单元映射、指纹对照的具体步骤与坑清单。
- `references/openfoam-facts.md`：已确认的 OpenFOAM-14 事实索引（源码路径、关键函数、字典键语义），用于省掉重复读源码。
- `scripts/make_of_case.sh`：从模板算例生成独立目录并运行，配置写进目录名。
- `scripts/of_log_summary.py`：把 OpenFOAM 日志整理成可靠表格（每步 `Co_max` → `max|U|`、残差、连续性），避免手工采样出错。
